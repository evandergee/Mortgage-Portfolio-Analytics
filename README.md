# Mortgage loan portfolio analytics (SQL Server)

An end-to-end SQL project on a **residential mortgage servicing book**: build a realistic
loan-level dataset, then answer the questions a portfolio / servicing / credit-risk analyst
is actually asked — amortization, delinquency roll rates, vintage curves, prepayment
speeds, and a CECL-style loss reserve.

```powershell
.\run_analysis.ps1
```

One script: generate ~4,000 loans and ~190,000 monthly performance records → build the
analytics layer → validate → run a guided tour. Needs SQL Server (Express is fine) with
the Chinook database (the `mtg` schema is created there) and `sqlcmd`. ~1 minute.

> The data is **synthetic** — generated by [`00_generate_portfolio.sql`](sql/00_generate_portfolio.sql)
> in the column layout of a Fannie Mae / Freddie Mac loan-level performance file. No real
> borrower data.

---

## What it demonstrates

| Mortgage / finance | SQL technique | Where |
|---|---|---|
| Fixed-rate **amortization** (P&I split, declining balance, adjusted final payment) | **recursive CTE**, `OPTION (MAXRECURSION 0)` | [`01_amortization.sql`](sql/01_amortization.sql) |
| Closed-form amortized balance `B_k = P(1+i)^k − PMT·((1+i)^k−1)/i` | set-based generation, `POWER`, no loops | [`00_generate_portfolio.sql`](sql/00_generate_portfolio.sql) |
| Portfolio stratification — **UPB, WAC, WAM**, WA FICO / LTV | UPB-weighted averages, `SUM() OVER (PARTITION BY)` | `mtg.vPortfolioMonthly`, `mtg.vStratification` |
| **Delinquency roll-rate matrix** (C → 30 → 60 → 90 → 120 → FC, cures, payoffs, liquidations) | month-over-month self-join + conditional aggregation (pivot) | `mtg.uspRollRateMatrix` |
| **Vintage / cohort analysis** — cumulative default & prepay by loan age and origination year | cohort join to an ages spine, censored-data handling | `mtg.vVintagePerformance` |
| **Prepayment speed** — SMM and annualised **CPR** | `CPR = 1 − (1 − SMM)^12` | `mtg.vPrepaymentSpeed` |
| **CECL-style expected loss** — `PD × LGD × EAD` by risk segment | assumption table join, LGD as a function of LTV | `mtg.vExpectedLoss` |
| Loan-level **data-quality / reconciliation** checks | one PASS/FAIL result set | [`03_validate.sql`](sql/03_validate.sql) |

## The pipeline

| Step | Script | |
|---|---|---|
| 0 | [`00_generate_portfolio.sql`](sql/00_generate_portfolio.sql) | `mtg.Loan` (origination) + `mtg.LoanPerformance` (monthly servicing). Each loan gets a "fate" — prepay (~11%), default (~3%), or still active — plus transient delinquency episodes. |
| 1 | [`01_amortization.sql`](sql/01_amortization.sql) | `mtg.uspAmortizationSchedule @LoanId` — the payment schedule via a recursive CTE. |
| 2 | [`02_analytics_layer.sql`](sql/02_analytics_layer.sql) | six views + `mtg.uspRollRateMatrix`. |
| 3 | [`03_validate.sql`](sql/03_validate.sql) | 7 checks: scheduled balance = closed-form amortization, contiguous history, zero-balance rules, valid statuses, portfolio sanity. |
| 4 | [`04_demo.sql`](sql/04_demo.sql) | guided tour of every object. |

## Glossary

**UPB** unpaid principal balance · **WAC** weighted-average coupon (note rate) · **WAM**
weighted-average maturity (months remaining) · **LTV / DTI** loan-to-value, debt-to-income ·
**DPD** days past due · **roll rate** share of a delinquency bucket that moves to the next
bucket next month · **vintage** group of loans by origination year · **SMM / CPR** single
monthly mortality / conditional prepayment rate (annualised) · **PD / LGD / EAD** probability
of default, loss given default, exposure at default · **CECL** current expected credit loss
(the US reserve-accounting standard) · **zero-balance code** why a loan left the book
(`01` prepaid, `09` default liquidation).
